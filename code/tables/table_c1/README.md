# Table C1

`generate_table_c1.m` reproduces Appendix Table C1 for the stable real-world
cases R1-R11. It combines accepted autocorrelation wave estimates with
derived velocities and the KLT-IV-based inverse-depth summary used for Figures
8 and 9.

The estimated group reports the case median KLT-IV streamwise surface
velocity, `U_s`, together with the accepted-map wavelength and amplitude.
`U_s` uses the same valid transects paired with the deep-water velocity
estimate in Figure 8.

## Required inputs

The accepted-map amplitude summary is read from the extracted Zenodo archive:

- `videos/derived/summaries/real_accepted_wsg_summary.csv`.

The velocity and depth summaries are generated by the repository's Figure 8
and Figure 9 workflows:

- `code/figures/figure_08/data/wse_autocorrelation_velocity_method_sensitivity_summary.mat`;
- `code/figures/figure_09/data/wse_autocorrelation_uniform_linear_power_depth_summary.csv`.

The MAT-file supplies accepted-WSG autocorrelation wavelengths and KLT-IV
surface velocities. The amplitude summary supplies the robust WSG amplitude.
The depth summary supplies the corresponding inverse-depth medians. For each
transect, it uses the largest admissible root where multiple roots exist and
the sole admissible root otherwise; a case median can therefore combine
deep-branch and unique-root estimates.

## Run

In MATLAB, from any working directory:

```matlab
repoRoot = 'C:\path\to\Water-surface-geometry-reconstruction';
addpath(fullfile(repoRoot, 'code', 'tables', 'table_c1'))
outputs = generate_table_c1( ...
    'C:\path\to\extracted-zenodo-archive', ...
    'C:\path\to\table_c1_output');
```

If the second argument is omitted, output is written to an `output` directory
beside the script. Generated output is ignored by Git.

The function writes:

- `table_c1_real_wave_hydraulic_results.csv`; and
- `table_c1_real_wave_hydraulic_results.tex`.

## Reproducibility notes

The generator validates that direct wavelength medians reproduce the
deposited deep-water velocities to the table's three-decimal precision under
`U = sqrt(g*lambda/(2*pi))`, with `g = 9.81 m s^-2`. Tiny full-precision
differences can arise for an even number of transects because the median is
taken before versus after the nonlinear transformation.

R12 and R13 are omitted under the stable-reconstruction inclusion mask. Linear
deep solutions are unavailable for R5 and R11. Power-profile deep solutions
are unavailable for R3, R5, R7, and R11. These values are rendered as `--`;
uniform-profile depths remain available for all R1-R11 cases.

The Figure 8 builder starts from the deposited per-transect KLT-IV velocity
and selected-profile data. The Figure 9 builder starts from the deposited
transect data and writes both the case summary and the depth-root audit. Thus
the displayed Table C1 medians can be traced to the contributing transects and,
for depth, to the selected admissible root.

The LaTeX output requires the `booktabs` package.
